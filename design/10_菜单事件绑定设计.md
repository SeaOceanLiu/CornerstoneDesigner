# 10_菜单事件绑定设计 — MenuBar/StatusBar/ContextMenu item 事件绑定

> 提出方：CornerstoneDesigner（UI 设计器）
> 状态：**设计通过并已实施/验收（2026-11-11；MenuBar/StatusBar/ContextMenu item 事件树已落地）**
> 关联：事件面板 F4、Menu/MenuBar 控件、`RegisterAction`、CR20261109001（Launcher Utility，独立联调中）

---

## 1. 目标

让设计器画布上的 `menu-bar` 控件，也能在右侧**事件页签**为菜单项绑定 `onClick`：

- 选中 `menu-bar` 后，事件页签显示该菜单的**菜单树**；
- 选择任意层级菜单项，填写/建议 handler，添加、更新、删除绑定；
- 绑定写入 `menu-bar.extended.menus[].items[].events.onClick`，随项目保存/加载/导出；
- 不改变现有菜单文本编辑方式，不影响主界面静态菜单的 `onClick` action 机制。

## 2. 现状与问题

| 环节 | 现状 | 问题 |
|---|---|---|
| 事件页类型表 | `kEventSpecs`（`src/CanvasPane.cpp:6929`）只含 button/label/edit-box/tree-view 等 | 无 `menu-bar` / `menu-item`，下拉为空 |
| 菜单项模型 | `menu-bar.extended["menus"]` 是嵌套 JSON；菜单项不是 `PlacedControl` | 事件页按 `m_selectedId` 查 `m_items`，无法选中菜单项 |
| 菜单项创建 | `CanvasPane::syncMenus`（`src/CanvasPane.cpp:3019`）只设置 caption/shortcut | 未回放 `events.onClick` |
| 菜单文本编辑 | `applyMenusText`（`src/CanvasPane.cpp:2949`）重建 menus，只保留标题/快捷键 | 即使手写 events，也会被后续文本编辑丢弃 |
| 静态主菜单 | `layouts/main_layout.json` 的 `onClick` + `App::registerActions` + `Engine LayoutParser` | 正常工作，但属于设计器自身 UI，不走项目事件页 |

## 3. 架构选择

### 方案 A（排除）：菜单文本语法加 handler

在 `menus` 文本行中增加 `@handler` 或 `|handler`。

- 优点：实现最小。
- 排除：改变现有菜单编辑语法和用户习惯；多层级/多事件时可读性差；仍然不在事件页签。

### 方案 B（采用）：menu-bar 选中时显示菜单事件树

- 选中 `menu-bar` 后，事件页签切换为“菜单事件”模式；
- 用 TreeView 展示菜单层级，选中节点后用现有 handler 编辑控件绑定；
- 数据直接写 `menus[].items[].events.onClick`，不引入菜单项 `PlacedControl`。

优点：

- 保留“在事件页签绑定”的习惯；
- 深层级用树缩进/展开/滚动，不需要路径输入；
- 不改 `m_items`、画布命中、放置、拖动、序列化主结构；
- 复用现有 handler 校验/建议命名/撤销。

### 方案 C（暂不采用）：菜单项一等控件 / 控件树虚拟节点

把菜单项纳入 `m_items` 或控件树虚拟节点，事件页复用通用控件事件。

- 优点：选中体验最统一，可扩展菜单项属性。
- 代价：菜单项不是画布布局控件，需改 `selectItem`、`syncTree`、`hitTest`、`placeControl`、`deleteSelected`、序列化、撤销和菜单重建映射；双模型易不一致。
- 结论：当前不做；若未来菜单项需要独立属性编辑，再按“虚拟节点”方案升级。

**定稿：方案 B + 菜单树。**

## 4. 数据模型

### 4.1 JSON 结构

在现有 `menu-bar.extended.menus` 的菜单项节点增加：

```json
{
  "caption": "打开…",
  "shortcut": "Ctrl+O",
  "events": {
    "onClick": "onMenuBar_Open_Click"
  },
  "items": []
}
```

- 仅支持 `onClick`（V1）；
- `separator` 节点不参与事件绑定；
- 顶层菜单节点（`menus[i]`）本身不是可绑定项，只有其 `items[]` 可绑定；
- handler 必须是合法 C 标识符，且在**整个项目**内唯一（含普通控件事件与菜单事件）。

### 4.2 稳定标识

菜单项没有独立 id；V1 使用**结构路径**作为 UI 选中标识：

```text
menu:<menuIndex>/<itemIndex>[/<itemIndex>...]
```

例如 `menu:0/2/1` 表示第 1 个菜单的第 3 个菜单项的第 2 个子项。

- **itemIndex 使用 `menus[i].items` 的原始数组下标，separator 也占一个下标**；不得跳过 separator 重新编号。否则在菜单项前插入/删除分隔符会让后续路径整体漂移，导致已有绑定错位。
- 示例：`menu:0/1` 是第 1 个菜单的第 2 个数组元素；若该元素是 separator，则没有可绑定事件，下一菜单项是 `menu:0/2`。
- 路径只用于 UI 选中和树刷新，不写入 JSON；
- 菜单文本编辑/重建后，路径可能变化；能匹配的旧事件保留，不能匹配的提示用户重新绑定（见 §6.2）；
- 不使用 caption 作为唯一键（允许重名；caption 只用于显示）。

### 4.3 handler 唯一性与命名

- 扩展 `CanvasPane::isHandlerNameUnique`：同时扫描 `m_items[].events` 与所有 `menu-bar.menus[].items[].events`（递归所有层级）。
- 建议命名：`on<MenuBarId>_<MenuItemCaptionPascal>_Click`，非法字符剔除，冲突自动追加 `2`、`3`…；
- 菜单项没有可读 id 时使用 caption；caption 为空时用 `Item`；
- 同一菜单项只保留一个 `onClick` handler；重复绑定 = 更新。
- **更新语义**：更新当前菜单项时，唯一性校验必须**排除该菜单项的旧 handler**（`A→B` 或 `A→A` 不应被自己的旧值判重）；建议先取下旧 handler，按新 handler 全局检查，失败则原样回滚，成功再写回并 `commitUndo`。
- “删除后重新添加同一 handler”应通过；删除本身进入撤销，重新添加是新的独立撤销步。

## 5. 事件页签 UI

### 5.1 触发模式

- 当 `m_selectedId` 的类型是 `menu-bar` 时，事件页签进入 **menu-event 模式**；
- 其他控件保持现有模式（`kEventSpecs` 过滤 + 已绑定 ListView）。

### 5.2 布局

在现有事件页签（`layouts/main_layout.json` 的 `tabEvent`）中，**动态创建**一个 TreeView，放在 `evHost` 内、已绑定 ListView 的位置；不新增静态 JSON 控件。

```text
事件
┌──────────────────────────────────────────────┐
│ [菜单事件树]                                 │
│  ▼ 文件                                      │
│      打开…            [onMenuBar_Open_Click] │
│      最近文件        [onMenuBar_Recent_Click]│
│        ├ a.csd                              │
│        └ b.csd                              │
│  ▼ 编辑                                      │
│      撤销            [onMenuBar_Undo_Click]  │
├──────────────────────────────────────────────┤
│ 事件: onClick（固定）                        │
│ handler: [onMenuBar_Open_Click........]      │
│ [建议命名] [绑定/更新]                       │
│ 错误提示                                     │
└──────────────────────────────────────────────┘
```

- `evMenuTree`：TreeView；节点 id = `menu:<path>`；label = caption + 已绑定标记（如 `打开…  ← handler`）；
- `ev_type`：菜单事件模式固定为 `onClick`，可禁用或隐藏，避免误选其他事件；
- `ev_handler`/`ev_suggest`/`ev_add`/`ev_err`：复用；`ev_add` 文案在菜单模式改为“绑定/更新”；
- 菜单模式新增 `ev_code`（代码）和 `ev_del`（删除）按钮，绑定行高 48，仅在选中菜单项且已有 handler 时启用；
- 菜单树改为 `tabEvent` 内的静态 TreeView（`evMenuTree`），位置固定在 `ev_handler` 行之后、按钮行之前；树显示时强制 `tabEvent` 重排，按钮/evtNote 落到树下方；隐藏树时不再强制重排，避免普通选中/打开工程触发整页重绘（P0-104 回归）；事件页签字体统一 18。
- 菜单模式下事件类型下拉固定显示并禁用为 `onClick`，handler 行显示当前菜单项事件。
- 已绑定 ListView 在菜单模式隐藏（树节点标签已显示 handler；如需统一列表，后续再加）。
- 空菜单/未选中节点：显示提示 `evtNote`，绑定按钮禁用。

### 5.3 交互

1. 选中 `menu-bar` → 构建菜单树，默认不选中任何菜单项；
2. 点击树节点 → 读取该节点 `events.onClick`，回填 handler；
3. “建议命名” → 按 §4.3 生成；
4. “绑定/更新” → 校验/唯一性检查 → 写入 `events.onClick` → `syncMenus` 回放 → `commitUndo` → 刷新树/标签；
5. “删除” → 删除当前节点 `events.onClick` → `syncMenus` 重新绑定 → `commitUndo` → 刷新；
6. 菜单文本编辑（属性面板 `menus` 行）后 → `applyMenusText` 重建模型；事件树刷新，尽量保留路径匹配的绑定。

## 6. 模型与同步

### 6.1 `syncMenus` 回放

- 递归创建菜单项时，在设置 caption/shortcut 后：
  - 若 `item.events.onClick` 存在且合法，设计期间**只用 `SetCallback(kEventClick, ...)` 打点**；
  - **不要**同时调用 `MenuItem::setOnClick`/`setCallback` 的引擎内部 m_onClick 路径，避免设计期双重触发；
  - 预览/导出由引擎 `LayoutParser` 按 `events.onClick` 查 action；宿主负责 `RegisterAction`；预览不额外叠加设计器回调。
- 重建菜单（`applyMenusText`）时先移除旧菜单面板，再按新模型创建；旧回调随旧控件销毁，无需手动解绑。
- **引擎菜单 click 延迟一帧执行**（P0-103 语义）：设计期打点/auto 探针需在下一帧 `ProcessEvents` 后检查，不能在点击当帧断言。
- 菜单项回调不能污染 `ScriptEventHandlers` 等宿主 action 表；设计期只做打点。

### 6.2 `applyMenusText` 事件保留

- 解析新菜单文本前，按旧树路径（含 separator 原始下标）建立 `path -> events` 映射，并**备份旧 `extended.menus`**；
- 解析后，对新树同路径节点恢复 `events`；
- 若路径不存在，丢弃并记录 `m_menuEventDropped` 数量；在应用文本前提示“结构变化可能导致 N 个事件绑定失效”，应用后状态栏再次提示；
- 不按 caption 全局匹配，避免重名串绑；
- 整个菜单文本应用（含事件丢失）进入**同一个撤销快照**；撤销后旧 `menus/events` 与设计期回调恢复，不能是不可逆的静默变更。

### 6.3 保存/加载/撤销

- `serializeLayoutJson` 已通过 `m.props.extended` 输出完整 `menus`，`events` 自动随带；
- 打开 `.csd` 时 `applyMenusText` 从模型重建菜单，`syncMenus` 绑定；
- `commitUndo` 快照包含 `extended.menus`，菜单事件绑定天然可撤销；
- 选择菜单项不进入撤销；绑定/更新/删除为独立撤销步（与普通事件一致）。

### 6.4 导出

- `collectEventBindings` 增加菜单项绑定；`EventBinding` 增加 **`menuPath`** 字段（普通控件为空串），避免同一 `menu-bar` 的多个菜单项导出成相同 `controlId + jsonEvent` 无法区分。
- 菜单路径建议用可读的 `菜单/子菜单/...`（由 caption 拼接，重名时附加数组下标），仅供 report/event_list/诊断，不作为持久化唯一键。
- 控件列使用 `menu-bar` id；事件列 `onClick`；handler 为 `events.onClick`；`menuPath` 写入 manifest。
- `event_list.json` 增加可选 `path`/`menuPath` 字段；消费方/测试同步，普通控件事件不改变现有结构。
- `buildEventsHeaderText` / `buildEventsSourceText` / C 宿主 / C++ 宿主均复用现有 handler 去重逻辑；
- 导出 layout JSON 的菜单项保留 `events` 字段；引擎按现有 MenuItem onClick 绑定。
- **不生成** `_comp_` 菜单事件（菜单不属于组件模板；如未来支持另议）。

## 7. 引擎配合

本设计**不需要新增引擎 API**：

- 引擎已支持 MenuItem `onClick`（LayoutParser 已有分支）；
- 事件树使用现有 TreeView 控件；
- 设计期回调使用现有 `Control::SetCallback`；
- 导出/预览沿用 `RegisterAction` + LayoutParser。

需要引擎确认的点：

1. `menus[].items[].events.onClick` 在 LayoutParser 中按现有 MenuItem 事件解析，不要求菜单项 id；
2. TreeView 节点的 `menu:<path>` id 仅设计器内部使用，不传给引擎；
3. 动态菜单重建后旧回调销毁/新回调绑定无额外生命周期要求；
4. 若菜单项需要 `enabled`/`checked` 等状态，另行扩展，不在本 CR；
5. **B6**：引擎在 `docs/schema/declarative-ui.schema.json` 的 menus 描述补 `items[].events.onClick`，并在事件/菜单手册确认示例可运行；`validate_layout --strict` 保持通过。此为文档契约补齐，不改变运行时。
6. **B4**：设计期只 `SetCallback`；预览由 LayoutParser 走 `m_onClick`，不重复注册设计器回调；click 延迟一帧。

## 8. 测试/验收

### 8.1 功能

- 选中 canvas `menu-bar` → 事件页出现菜单树；深层子菜单展开可见；
- 选中菜单项 → handler 回填；建议命名不冲突；
- 添加/更新/删除绑定 → 树标签/错误提示/状态栏正确；
- `syncMenus` 设计期点击菜单项打印 `[Events] ...`；
- 保存/打开往返保留 `events.onClick`；
- 撤销/重做恢复绑定；
- 导出 JSON 保留 events；`events.h/.c`、`event_list.json`、C/C++ 宿主包含 handler；
- 菜单文本编辑后路径相同则保留绑定，路径消失则提示且可撤销；
- **separator 计数**：在菜单项前/后插入或删除 separator，后续绑定路径不漂移；
- **同一 menu-bar 多个菜单项绑定**：导出 event_list/report 的 `menuPath` 可区分；
- 更新同一项 handler（A→B、A→A）、删除后重新添加同一 handler 均通过；
- 设计期菜单点击打点在下一帧 `ProcessEvents` 后出现，且只出现一次（无 m_onClick 双重触发）；
- 普通控件事件面板不回归。

### 8.2 自动化

- `auto=2` 增加：菜单树构建、绑定/更新/删除、唯一性（含更新排除旧值）、separator 路径、保存打开往返、导出事件/menuPath、延迟一帧打点；
- `auto=3` 增菜单树显示/切换探针；
- 回归：`auto=2` 全量、`auto=3`、`strict`、Release 零警告。

### 8.3 手工

- 深层菜单（≥4 层）展开/滚动/选中；
- 菜单项重名、中文 caption、空 caption、分隔符、深层子菜单；
- 菜单文本重排后绑定保留/失效提示、撤销恢复；
- 同一 menu-bar 多项绑定、更新/删除/重加。

## 9. 风险

| 风险 | 处理 |
|---|---|
| 菜单结构变化导致路径失配 | §6.2 路径映射（含 separator 下标）+ 应用前提示 + 撤销；不做 caption 模糊匹配 |
| handler 重名 | 扩展全局唯一校验；建议命名自动编号 |
| 树节点过多 | TreeView 展开/收起/滚动；后续可加搜索 |
| 菜单文本/事件双入口 | 事件只写 `events`，菜单文本只写 caption/shortcut；两者共用同一 JSON；结构变化前备份/提示并进入撤销 |
| 预览无 action 注册 | 与现有普通事件一致，预览只验证菜单展开；不承诺业务 handler 执行 |
| 深层菜单 UI 高度不足 | 树在 `evHost` 内滚动，绑定行固定；必要时折叠 |

## 11. 评审结论/待评审问题答复

1. **菜单树放 `evHost` 动态 TreeView**：接受；实现时保证滚动、空树提示、深层展开/收起。
2. **路径失配**：按设计**丢弃并提示**，不做 caption 迁移；应用前备份旧 `menus`，提示可能失效数量，且整次文本修改进入撤销快照。
3. **预览是否执行 handler**：V1 **不执行**；预览只验证菜单树/菜单展示，不额外注册 preview action，不改变现有预览事件语义。

## 12. 其它 item 级控件适配分析

| 控件/条目 | 现有能力 | 是否可直接复用菜单事件模型 | 需要引擎 |
|---|---|---|---|
| StatusBar items | `items[].events.onClick` 已解析并绑定；设计期 `status-item-click` 打点，导出/预览由 LayoutParser 执行 | 已实施：`status:<index>` 事件树、行式 items、全局唯一校验/导出 | **CR20261109002/10002 已关闭** |
| ContextMenu items | 独立 `context-menu` items/events 已解析；设计器 items 行式编辑、`ctx:<index>` 事件树 | 已实施：目标控件 metadata、条目事件、无 remove API 时重建 | **CR20261109003/10003 已关闭** |
| TabControl tabs | 控制级 `onTabChange` 已支持；无页签级 onClick/事件数组 | 若做页签级事件，需要引擎定义 tab item 事件路径 | 暂不提，按需求另立 |
| ListView rows/cells | 控制级 cell-edit-* 事件已支持；无逐行/逐 cell click 的 JSON 事件模型 | 可复用 item 路径模式，但需引擎 item/cell 事件契约 | 暂不提，按需求另立 |
| TreeView nodes | 控制级 select/编辑事件已支持；无逐节点 onClick JSON 模型 | 同上 | 暂不提，按需求另立 |
| ComboBox items | 控制级 selection-changed 已支持 | 通常无需逐项事件 | 不需要 |

结论：

- 菜单事件树的设计可抽象为通用的 **item path + events.onClick + handler**，但只有在引擎具备 item 解析与回调绑定的控件上才能直接复用。
- StatusBar 是引擎已有 onClick 槽位但实现为空的优先修复项；ContextMenu 需要引擎补 items 解析。
- 设计器侧的事件树/校验/导出可在对应引擎能力交付后复用，不在本设计首期实现。

## 13. StatusBar / ContextMenu 设计器实施补充（2026-11-10）

- StatusBar：事件页按 `status:<index>` 扁平 item 树绑定 `items[].events.onClick`；设计期通过 `status-item-click` 段索引回调打点，导出/预览由引擎 LayoutParser 绑定。
- ContextMenu：属性面板新增 `items` 行式编辑（`caption@shortcut`，`--` 分隔）；事件页按 `ctx:<index>` 绑定 `items[].events.onClick`；由于引擎暂无 remove-item C ABI，items 变化时重建 ContextMenu 控件并复用模型样式/事件。
- 两类的 EventBinding.menuPath、全局唯一校验、代码/删除按钮、保存/撤销/导出均复用菜单事件路径。

## 14. 2026-11-11 as-built 补充

- MenuBar：事件树节点 `menu:<menuIndex>/<itemIndex>...`；菜单文本只编辑 caption/shortcut，事件写入 `menus[].items[].events.onClick`；separator 占下标但不绑定。
- StatusBar：`items` 行式格式为 `文本@样式...`（一行一段），事件树节点 `status:<index>`；设计期点击打点，导出/预览执行 handler。
- ContextMenu：`items` 行式格式 `caption@shortcut` / `--`；事件树节点 `ctx:<index>`；目标控件由属性面板 ComboBox 选择，映射保存在 `.csd metadata.contextMenuTargets`（target 可为控件 id 或画布 bench id）。
- ContextMenu 导出：C/C++ 宿主在 LoadLayout 后 `FindControl` + `SetPtr("context-menu", menu)`；画布根目标使用 `Root()/GetRoot()`。
- 事件面板的 MenuBar/StatusBar/ContextMenu 条目树均支持代码编辑、删除、handler 唯一性校验和撤销；items 文本变更会重放并保留同路径事件。
- 设计文档 `design/04` 的旧“动态加行/删行”描述以本节实际行式编辑为准。
