# 07_容器类子控件编辑设计 — 容器类控件的子控件放置/选中/拖动（P1）

> 提出方：CornerstoneDesigner（UI 设计器）
> 状态：**设计草案，待评审**
> 关联：用户需求（2026-09-30）——Popup 等容器类控件承载子控件；引擎清单 P0-28（编辑态常显）已落地

---

## 1. 目标

容器类控件（**Panel / WinFrame / Popup / Dialog / TabControl 页**）支持**往内部放置、选中、拖动子控件**——画布交互从"顶层控件编辑"升级为"层级化编辑"。

## 2. 现状

| 环节 | 现状 |
|---|---|
| 放置 | `placeControl` 统一 AddChild 到**画布根**（bench），无容器目标概念 |
| 选中 | 画布 hitTest 仅遍历 `m_items`（顶层控件），容器内部不可达 |
| 拖动 | 顶层控件拖动（容器整体）；容器内子控件无拖动 |
| 控件树 | 引擎树层级可见（syncTree），但树点击选中仅顶层语义 |

## 3. 引擎能力盘点（已核实）

| 能力 | 现状 | 设计器可用性 |
|---|---|---|
| WinFrame 内容面板 | `GetPtr("client-panel")` 返回 ClientPanel 句柄（WinFrame.cpp:591） | ✓ 直接可用 |
| 子控件枚举 | `ControlBase::getChildren()` 返回 `vector<shared_ptr<Control>>`（含引擎内部子控件，需过滤） | ✓（配合设计器模型树过滤） |
| 命中检测 | `drawRect.contains`（设计器自算）+ 引擎 `isContainsPoint` | ✓ 自算可行 |
| TabControl 页访问 | TabAddPage/TabSetPage/TabSetTitle 有；**GetPagePanel/current-index 属性键缺** | ✗ 需引擎配合 |
| Popup 编辑态 | 常显已落地（close-on-click-outside=0） | ✓ |

## 4. 核心机制

### 4.1 模型层：m_items 树化
- `ControlModel` 增 `parentId`（扁平存储 + 父指针语义）；`m_items` 收纳**全部控件**（顶层 + 容器子控件）。
- 顶层判定：parentId 空 → 画布根子控件；非空 → 容器子控件。
- 兼容：既有单层逻辑（z 序/序列化）按 parentId==空 过滤，行为不变。

### 4.2 容器解析（放置/命中的目标容器）
- **内容面板映射**：WinFrame → `GetPtr("client-panel")`；Panel/Popup/Dialog → 自身；TabControl → 当前页（P2，依赖页访问 API）。
- **画布点击的容器解析**：hitTest 自顶向下（z 序逆序）遍历 m_items——命中容器类控件且点在其**内容区**（WinFrame 为标题栏以下）→ 放置/选中目标深入该容器；命中容器**框架区**（标题栏/边框）→ 选中/拖动容器本体。
- **放置目标双通道（2026-09-30 定稿，两者都支持）**：①**画布命中**——放置模式下点击容器内容区 → 目标=该容器（点哪放哪）；②**控件树显式指定**——树中选中容器 → 目标=该容器。两通道均更新"当前放置目标"（最新者优先），状态栏提示当前目标容器（视觉高亮 P1-b 润色）。
- **WinFrame 严格约束（定稿）**：子控件**只能放入 ClientPanel**（内容区命中→深入 ClientPanel；标题栏/窗框=容器本体选中/拖动）——不放窗体本体。

### 4.3 坐标换算
- 放置/拖动的子控件 rect 为**相对容器内容区**坐标：画布逻辑坐标 − 容器内容区原点（含 zoom/滚动换算，复用既有视口反变换链）。
- 容器拖动时子控件跟随（引擎父子变换既有行为，验证即可）。

### 4.4 选中与拖动
- **选中**：hitTest 深度优先（子控件优先于容器——同一命中点取最深层可交互控件）；子控件选中后属性面板编辑（type 按子控件 schema）。
- **子控件拖动**：钳制在容器内容区（不越界）；容器整体拖动仅框架区触发。
- **删除**：子控件删除 = 从容器摘除（引擎 removeControl）+ 模型清理。

### 4.5 序列化
- 布局输出按引擎树层级嵌套（容器 children 内嵌——LayoutParser 既有语法），parentId 链还原嵌套结构。

## 7. 风险

- **事件竞争**：容器内子控件的画布事件（点击选中）与引擎控件自身交互（Button 点击）竞争——设计器画布为**设计态快照**（子视口禁交互既有语义），风险低；联测验证。
- **m_items 树化的兼容面**：z 序/序列化/删除等既有逻辑的 parentId 过滤遗漏——逐项梳理（§4.1）。
- **引擎内部子控件混入**：getChildren 含 caption-label 等——模型收纳需按"设计器放置来源"标记过滤。

## 8. 评审结论（2026-09-30 定稿）

1. 放置交互：**双通道都支持**（画布命中深入 + 树选中显式指定，最新者优先）——定稿。
2. **WinFrame 子控件只能放入 ClientPanel**（严格约束）——定稿。
3. 分期切分（P1-a 先 Panel/WinFrame）——**确认可行**。
