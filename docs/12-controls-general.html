12 控件通用操作

工具箱中的控件放置到画布后，使用流程基本一致：选中控件、在属性面板填写属性、在事件面板绑定事件、在预览或导出结果中验证。本章先讲通用操作，后续章节再按控件类型说明具体字段和使用方式。

12.1 从放置到运行

  1. 在工具箱中双击或拖拽控件，按 工具箱与放置 的规则放到画布或容器中。
  2. 在画布或控件树中选中控件；右侧属性面板显示该控件可编辑的字段。
  3. 填写控件 ID、位置尺寸、文本、颜色和控件专有属性。
  4. 切换到“事件”页签，按 事件面板 的方法绑定 handler。
  5. 按 F5 或画布工具栏“预览”检查运行时效果。
  6. 最后保存工程，并按需要导出 JSON 或 C/C++ 工程。
控件 ID 是代码和事件绑定引用的名字。建议在开始绑定事件前先改成有意义的 ID，例如 saveButton，避免后续重命名引发引用同步。

12.2 通用属性

字段用途注意
控件 ID代码、事件和父子关系引用工程内唯一；不要使用空白或 C/C++ 关键字
X / Y / 宽 / 高相对父容器的位置和尺寸容器子控件的坐标相对容器内容区
锚点窗口或父容器变化时的定位方式需要跟随拉伸时优先用锚点，不写死坐标
可见 / 启用控制是否显示、是否响应交互隐藏控件通常也不参与命中
文本 / 内容Label、Button、EditBox 等的主文本具体字段随控件类型变化
颜色 / 字体背景、文字、边框和状态色项目主题也可能覆盖未显式设置的通道
控件专有属性items、columns、rows、tabs、menus 等复杂字段通常提供行式编辑，也可用原始 JSON

属性面板会根据控件类型和 schema 显示动态字段；未在面板中出现的属性仍会保留在工程 JSON 中。字段含义的完整列表见 附录 B。

12.3 容器、父子关系与层级

  • 控件落在 Panel、WinFrame 客户端区或 TabControl 当前页时，会成为该容器的子控件。
  • 控件树中越靠下的同级节点越靠前绘制；层级通过控件树右键菜单调整。
  • 移动控件到另一个容器后，坐标语义改为相对新父容器。
  • 容器属性会参与布局；删除父容器会连同子树一起删除。

容器专有操作见 容器与布局控件。

12.4 事件绑定

  • 事件名和参数由控件类型决定；在事件页签中选择实际存在的事件。
  • MenuBar、StatusBar、ContextMenu 的条目事件是分级编辑的，需要先在条目上选择事件，再填写 handler。
  • 同一个 handler 可以被多个控件共享；但参数含义可能不同，需在代码中判断来源。
  • 导出 C/C++ 工程时，事件绑定会生成函数骨架；只导出 JSON 时只保留事件字段。

具体操作见 事件面板；各控件常用事件见后续控件章节和 附录 C。

12.5 三种编辑方式

方式适合注意
画布 + 属性面板单个控件的常规属性修改立即生效，并进入撤销栈
行式结构化编辑items、menus、columns、rows、tabs 等列表按字段提示的格式一行一项；空行通常忽略
原始 JSON批量数据、面板尚未覆盖的字段应用前确认控件 ID 和父节点，错误可能使子树丢失

12.7 使用后的自检

  1. 在控件树里确认控件位于预期的父容器，而不是画布根或错误的面板。
  2. 确认控件 ID 唯一，事件绑定列表中没有指向旧 ID 的残留。
  3. 用预览检查文字、资源和交互；不要只依赖设计画布。
  4. 导出后检查生成工程中的控件 ID、事件名和资源路径。
