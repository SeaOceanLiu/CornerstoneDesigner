33 导出与集成

导出把设计器中的工程转成运行时可用的产物。不同导出方式适合不同阶段：先导出 JSON 给现有宿主，或直接导出可编译 C/C++ 工程做完整验证。

33.1 导出方式一览

方式菜单典型用途
保存工程文件 → 保存 / 另存为继续用设计器编辑，保留组件/事件/主题
导出 JSON文件 → 导出 JSON交给已有 UICornerstone 宿主加载
导出 C 工程文件 → 导出为可编译C项目裸 C ABI 宿主，最小依赖
导出 C++ 工程文件 → 导出为可编译C++项目C++ Binding 宿主，带 binding 包
导出报告文件 → 导出项目报告项目说明、控件/事件清单、布局截图

33.2 导出 JSON

  1. 选择 文件 → 导出 JSON。
  2. 选择目标文件和目录。
  3. 导出的 JSON 包含控件树、viewport、theme（如果有）、组件定义和事件字段。
  4. 把它交给 UICornerstone 宿主，在运行时通过 LoadLayout 加载。
导出 JSON 不包含设计器专用的元数据（例如 handler 代码编辑内容），需要事件代码时请使用 C/C++ 工程导出。

33.3 导出 C 工程

选择 文件 → 导出为可编译C项目，然后选择空目录。设计器生成 C11 宿主工程，典型文件：

文件作用
main.c加载 DLL、创建实例、加载 layout.json、注册事件、帧循环
layout.json运行时布局
events.h事件函数声明
events.c事件函数骨架/已编辑实现
event_list.json机器可读的事件清单
CMakeLists.txt构建脚本，自动拷贝运行依赖
README.md导出工程的使用说明

33.4 导出 C++ 工程

选择 文件 → 导出为可编译C++项目。与 C 工程类似，但宿主是 C++ Binding，并包含 binding/ 包。典型文件：

  • main.cpp：C++ Binding 宿主。
  • events.h / events.c：事件声明与实现骨架。
  • layout.json / event_list.json。
  • CMakeLists.txt、README.md、binding/。

33.5 编译和运行导出工程

  1. 进入导出目录，阅读 README.md。
  2. 确保 CMake 与 Visual Studio C++ 工具链可用。
  3. 按 README 中的命令配置和构建。
  4. 构建后，运行依赖（DLL/layout/assets）会被拷贝到可执行文件旁。
  5. 运行程序验证布局与事件。

导出工程按“exe 同目录/工作目录”解析 DLL、layout.json 和 assets；从任意目录启动时请确保工作目录正确。

33.6 资源和 provider

布局中的 provider:名称/路径 引用会随 layout.json 的 resourceProviders 块保留。导出时请把对应资源目录一并交给宿主，或在导出目录中补齐资源。资源缺失不会使设计器崩溃，但运行界面可能缺图/缺字体。

33.7 导出项目报告

选择 文件 → 导出项目报告，选择输出目录。报告包含：

  • report.md：工程文件、画布尺寸、控件清单/分布、事件绑定、资源等信息。
  • screenshot.png：优先从预览实例捕获的 1:1 布局截图。

报告适合评审、交付说明和问题复现。截图不包含设计器网格与选中框。

33.8 导出前检查

  • 事件 handler 名称合法、无冲突。
  • 组件模板和 props 已应用，实例显示正确。
  • 资源路径有效，预览能正常显示。
  • 项目主题已在预览中验证。
  • 导出目录为空或允许覆盖。
导出工程中的 events.c、layout.json 等文件由设计器生成。需要长期修改业务逻辑时，建议在导出工程中维护；再次导出可能覆盖这些文件。
