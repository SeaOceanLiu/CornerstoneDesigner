附录 C 事件速查

事件键名来自 UICornerstone 声明式布局。设计器事件面板会根据控件类型过滤可用事件；完整列表以当前引擎版本为准。

C.1 事件键名与控件

事件键适用控件说明
onClickButton、可点击 Label、菜单项点击
onCheckChangedCheckBox勾选状态变化
onTextChangedEditBox、TextArea文本变化
onEnterEditBox、TextArea回车
onValueChangedProgressBar、Slider、NumericUpDown数值变化
onSelectionChangedComboBox、ListView选中项变化
onColumnSortListView列排序
onCellEditBeginListView单元格开始编辑
onCellEditedListView单元格提交编辑
onCellEditCancelListView取消单元格编辑
onSelectTreeView节点选中

onNodeEditCancelTreeView取消节点编辑
onTabChangeTabControl页签切换
onSplitterMovedSplitter分割条移动

onConfirm / onCancel / onCloseDialog、WinFrame确认/取消/关闭
onClick（items）MenuBar / ContextMenu / StatusBar菜单项点击

C.2 组件事件

组件模板内部的事件键需要加 _comp_ 前缀，例如 _comp_onClick。实例层事件面板会列出模板声明的键，并把实例绑定映射到宿主 handler。

模板按钮事件：
  events: { "onClick": "_comp_confirm" }

实例事件：
  events: { "_comp_confirm": "onDialogConfirm" }

导出时生成 onDialogConfirm，不会生成 _comp_confirm 的函数体。

C.3 handler 命名规则

  • 合法 C/C++ 标识符：字母/下划线开头，只含字母、数字、下划线。
  • 不能使用 C/C++ 关键字。
  • 建议使用 PascalCase，例如 onLoginClick、onListSelectionChanged。
  • 同一 handler 被多个控件复用时，确认这是有意的共享逻辑。

C.4 事件不触发的检查顺序

  1. 控件是否处于 enabled 状态。
  2. 事件类型是否被该控件支持。
  3. 绑定是否在正确的控件上（组件实例 vs 模板控件）。
  4. 预览/导出工程中是否注册了 handler。
  5. 导出 events.c 中函数体是否为空骨架。
  6. 运行时控制台是否报告未注册 action 或加载失败。
