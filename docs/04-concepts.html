5 核心概念

理解下面几个概念，后面的操作会容易很多。

5.1 工程、布局与控件树

  • 工程（Project）：设计器保存的 .csd 文件，包含布局、组件、事件代码、主题和元数据。
  • 布局（Layout）：控件树 + 画布尺寸 + 运行时主题。导出 JSON 时主要导出这一部分。
  • 控件树：控件之间的父子关系。控件树决定布局容器的嵌套关系，也决定绘制顺序。

5.2 控件、ID 与坐标

每个控件都有类型、ID、位置、大小和属性。ID 用于代码引用、事件绑定和查找控件。

  • ID 在同一布局中应唯一；重复时设计器会自动追加编号或提示。
  • X、Y 是控件相对父容器的坐标；宽、高是控件尺寸。
  • 根级控件的父容器是画布（Bench）。
  • 容器控件（Panel、TabControl 页、WinFrame 内容区等）有自己的内容区，子控件相对内容区定位。

5.3 显式属性与主题属性

控件最终外观来自两类来源：

  1. 显式属性：你在属性面板、JSON 或代码中直接设置的值。
  2. 主题属性：项目主题按选择器匹配后计算出的值。

显式属性优先于主题。如果某个控件已经显式设置了颜色，主题规则不会覆盖它；如果希望主题生效，请清除该控件的显式覆盖或改用类/主题统一管理。

当前版本的设计画布以显式样式和选中状态为主；项目主题主要在预览、报告截图和导出运行界面中体现。主题规则本身不会改变控件矩形。

5.4 组件与实例

  • 组件定义：一棵可复用模板，包含若干控件，可声明 props。
  • 组件实例：在设计器中放置的组件节点，保存自己的 props 值和事件绑定。
  • 模板：组件内部的控件结构；编辑组件时修改的是模板。
  • 幽灵展开：设计器在画布上展开实例的模板以便查看，幽灵控件不保存、不参与选择。

5.5 事件与 handler

事件由“控件 + 事件类型 + handler 函数名”组成。设计器负责收集绑定并生成 C/C++ 事件代码；运行时由 UICornerstone 在事件发生时调用对应 handler。

组件模板中的事件使用 _comp_ 前缀，实例层再把它们映射到宿主 handler，这是组件复用的关键机制。

5.6 资源提供者

资源提供者把“资源名”映射到磁盘目录。布局中的图片、字体、动画通过 provider:名称/相对路径 引用资源，而不是写死绝对路径。这样工程迁移或导出时更容易复用。

5.7 主题、类、变体与条件

概念说明
变量--name 名称与值，规则中用 var(--name) 引用
规则selector + declarations，例如 button.primary
类给控件打的标签，例如 primary，供 .primary 选择器匹配
变体在基础主题之上叠加的命名样式，例如 dark
媒体条件根据视口宽高/方向/缩放匹配的规则
容器条件根据某个祖先容器的尺寸匹配的规则

5.8 撤销与未保存状态

可撤销的编辑会进入撤销栈。连续修改同一属性可能合并为一步，避免撤销时逐个字符回退。窗口标题中的 * 表示当前工程有未保存修改。

关闭窗口前请确认已保存。当前版本没有自动保存恢复流程；请不要把 .csd 只留在内存中。
