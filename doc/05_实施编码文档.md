## 1. 实施计划

### 阶段零：依赖构建（Day 0–1）

- `git clone --recursive` 获取全部子模块（`subModules/UICornerstone` 及 UICS 自身的依赖）
- 构建 UICornerstone SDL3 后端：`cd subModules\UICornerstone && build_scripts\build.bat sdl3`
  - 产出核心 DLL（`UICornerstone.dll`）、后端 DLL（`UIBackend_sdl3.dll`）与 SDL3 运行库、assets
  - 验证 binding 样例可运行：`cmake --build subModules\UICornerstone\build\binding --config Debug` → `sample_cpp_hosted.exe backend=sdl3 auto=3` 干净退出
- 验收：依赖 DLL 就绪，Binding 样例在无人值守模式下 exit=0

### 阶段一：工程骨架（Day 1）

- 创建根 CMakeLists.txt：`add_subdirectory(binding)` 引入 UICornerstoneBinding，链接设计器目标
- 配置 POST_BUILD 拷贝（核心 DLL/后端 DLL/SDL3 运行库/assets → 设计器输出目录）
- 创建设计器自身 JSON 布局骨架（`layouts/main_layout.json`，坐标定稿见 doc/03 概念设计 §2 / doc/04 详细设计 §9）
- App 框架：`UICornerstone::Create(Config)` + Embedded 循环 + `LoadLayout` 骨架 + `RegisterAction` 桥接
- 验收：`build_scripts\build.bat sdl3` 通过，窗口显示骨架布局，`auto=<秒>` 干净退出

### 阶段二：核心模型与序列化（Day 2–3）

- ControlModel、SRect、EventBinding 数据结构
- Serializer（LayoutParser 兼容 JSON 导入/导出 + `.csd` 项目格式 + 未知字段保留）
- 单元测试：往返一致性、颜色格式（#RRGGBBAA/6 位/对象）、中文
- 验收：单元测试全过（exit=0）

### 阶段三：业务逻辑层（Day 4–5）

- ProjectManager（创建/保存/加载/导入/最近文件，Win32 文件对话框薄封装）
- EventManager（事件增删查改、命名检查、建议、注册表 §3.2）
- CodeGenerator（events.h/events.c/event_list.json 生成、项目报告）
- LayoutEngine（排版、对齐吸附、Z-Order、坐标反变换）
- UndoRedoService（命令模式、50 步栈、合并策略）
- 单元测试：每模块独立用例
- 验收：单元测试全过（exit=0）

### 阶段四：设计器 UI 集成（Day 5–9）

- 工具箱面板（类型注册表驱动，动态创建控件项）
- **左/右栏 Tab 切换组件**（自研薄层：Label 切换钮 + 内容 Panel 互斥 visible；左栏三 Tab 含**资源面板 P1**：resourceProviders 两列 name/path 行内增删改）
- **画布工具栏**（缩放百分比 ComboBox、−/1:1/+ 按钮、网格/对齐 CheckBox、**对齐/分布下拉组（选中 ≥2 启用）**、设计/预览切换）
- 画布区：子视口 + `SetViewportScaleMode/SetCanvasSize` 缩放 + 鼠标反变换拖拽放置/移动
- 选中与控点（`CreateHandleControl`）、多选、对齐辅助线、Z-Order 菜单动作（含上移/下移）
- **对齐/分布命令**（多选 ≥2 时启用：左/中/右、顶/中/底、等宽/等高、水平/垂直分布，入 Undo 栈）
- **网格 / 对齐参考线**（程序生成纹理经 `AdoptResource` 内存资源 + `CreateImage`，自研薄层）
- 控件树面板（`CreateTreeView` 展示内存模型，选中↔画布↔属性三联动；右键菜单 P2，P1 用菜单动作 + 属性面板 id 编辑替代）
- 属性面板动态表单（NumericUpDown/ColorPicker/ComboBox/EditBox/CheckBox + 布局引擎属性 + 分组 + 多选交集 + 重置）
- 事件面板 + 预览注册（`RegisterAction` 实演）
- 撤销/重做 UI 绑定（菜单 + Ctrl+Z/Y）
- 窗口标题（项目名 + 未保存 `*`，`SDL_SetWindowTitle`）与无项目状态（画布提示 + 面板禁用）
- 内嵌预览（预览子视口 + 防抖 300ms）
- 验收：完整交互流程人工走查 + 集成测试全过

### 阶段五：导出与打磨（Day 10–12）

- 完整导出（layout.json / events.h+c / 报告）
- 兼容性验证：导出 JSON 对照 UICornerstone `test_layout`/`test_layout_advanced` 输入规格
- 性能测试：200+ 控件编辑流畅度（N3 ≥ 30FPS）
- 验收：验收测试 AT1–AT9 全过

## 2. 编码规范

### 通用规范

- C++17 标准
- 编码/设计/测试规范遵循 `design/guidelines/`（每次编码前通读 [coding.md](../design/guidelines/coding.md)）
- 所有源代码文件（.h/.cpp）编码：**UTF-8 with BOM**
- 涉及 UICornerstone 的操作遵循其既定规则（位置数据存储、颜色 #RRGGBBAA、NOMINMAX 前置等），见 `design/guidelines/design-rules.md`

### 命名规则

| 元素 | 规则 | 示例 |
|------|------|------|
| 类 | PascalCase | ControlModel |
| 方法 | pascalCase | toJson |
| 成员变量 | m_camelCase | m_undoStack |
| 参数 | camelCase | controlId |
| 常量 | kCamelCase（具名常量，禁魔鬼数字） | kSnapThreshold |
| 宏 | UPPER_SNAKE | DESIGNER_MAX_UNDO |

### 文件头

```cpp
// <filename>
// CornerstoneDesigner
//
// <description>
```

## 3. 依赖项与工程结构

| 依赖 | 来源 | 用途 |
|------|------|------|
| UICornerstone | git submodule（`subModules/UICornerstone`） | UI 框架 + LayoutParser + 全部控件 |
| UICornerstoneBinding | UICS `binding/` 工程编译 | C++ Binding 静态库（纯动态加载） |
| nlohmann/json | UICS 子模块内 | JSON 解析与序列化 |
| SDL3/SDL3_ttf/SDL3_image | UICS 子模块内 | 窗口、渲染、字体、图片（运行期 DLL） |

### CMakeLists.txt 结构概要

```cmake
cmake_minimum_required(VERSION 3.16)
project(CornerstoneDesigner C CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

if(WIN32)
    add_compile_options(/utf-8 /FS)
endif()

set(UICORNERSTONE_ROOT ${CMAKE_CURRENT_SOURCE_DIR}/subModules/UICornerstone)

# C++ Binding 静态库（独立于核心库构建；经 LoadLibrary 动态加载核心/后端 DLL）
add_subdirectory(${UICORNERSTONE_ROOT}/binding ${CMAKE_BINARY_DIR}/binding)

# 设计器
add_executable(CornerstoneDesigner
    src/main.cpp
    src/App.cpp
    src/ControlModel.cpp
    src/Serializer.cpp
    src/ProjectManager.cpp
    src/EventManager.cpp
    src/CodeGenerator.cpp
    src/LayoutEngine.cpp
    src/PreviewEngine.cpp
    src/UndoRedoService.cpp
)

target_include_directories(CornerstoneDesigner PRIVATE include)
target_link_libraries(CornerstoneDesigner PRIVATE UICornerstoneBinding)

# 运行依赖 POST_BUILD 拷贝（参照 UICS binding/CMakeLists.txt 模式）：
#   UICornerstone.dll + UIBackend_sdl3.dll + SDL3*.dll + assets/
#   来源：UICornerstone build/sdl3/Debug/ 与 subModules/assets/
```

> 设置 `-DUICORNERSTONE_CORE_OUTPUT=<UICS build/sdl3/Debug>`（binding 子工程的 DLL 拷贝来源，缺省即 UICS 默认输出，通常无需显式指定）。

## 4. 构建与验证

```batch
# 克隆（含子模块）
git clone --recursive git@github.com:SeaOceanLiu/CornerstoneDesigner.git

# 首次：构建 UICornerstone（提供运行依赖 DLL，见阶段零）
cd subModules\UICornerstone
build_scripts\build.bat sdl3
cd ..\..

# 构建设计器
build_scripts\build.bat sdl3

# 运行
build\sdl3\Debug\CornerstoneDesigner.exe
```

### 提交前验证

按顺序执行：

1. `cmake --build build --config Debug` — 必须零警告
2. 运行存在的测试（核心逻辑单元测试 + 集成测试，`auto=<秒>` 无人值守）
3. `git submodule status` — 指向正确 commit

## 5. 版本控制

- 每个阶段完成后原子提交
- 提交信息格式：`阶段X: 简短描述`
- 不提交 `build/`、`Temp/`、`*.csd.autosave`
- UICornerstone 作为 submodule 管理，不修改其内部文件；依赖 UICornerstone 能力变更时先在其仓库提交，再更新 submodule 指针
